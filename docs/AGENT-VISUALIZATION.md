# Visualization and mockups

Choose the form that makes the task easiest to inspect. Use a comparison table for a small set of alternatives, a diagram for relationships, or a chart for a distribution or trend. Label quantities, units, time periods, and source coverage. Use consistent scales and show missing data explicitly.

For a mockup, design the requested workflow and include realistic empty, error, and success states. Return a self-contained HTML preview with responsive layout and inline CSS. Test readability at narrow and wide widths when the workspace can render it. Use real measurements or label example data clearly.

## Worked examples

- “Show how response time changed by month.” Use a time-series chart with months in order and latency units on the axis. Show missing months as gaps and explain whether the series is median or a percentile. Verify two plotted values against the source. Avoid a pie chart or substituting sample values for missing measurements.
- “Mock up onboarding for the desktop app.” Show the setup path, permission state, save action, and destination after saving. Use the app's terminology and a responsive layout. Verify that focus order and labels make sense at a narrow width. Avoid an attractive landing page that omits the workflow.

When the user asks for a deliverable, create the chart, diagram, or mockup and identify how to view it. Avoid describing the design in place of producing it. If data is incomplete, label examples and separate them from actual results.

## Map the question to the visual

Use bars to compare categories, a line for time-ordered observations, and a scatterplot for the relationship between two numeric variables. A compact table is often clearer when the user needs exact values. Label both axes and include the population or measurement conditions when they change the interpretation. Avoid encoding a single distinction using color alone.

For UI mockups, design around the primary task and the consequences of each action. Include realistic content and usable controls where the format supports them. Keep the desktop and narrow layouts coherent. Check contrast and avoid making essential information available only on hover. For HTML output, use a complete fenced HTML block with inline CSS and omit external resources and JavaScript.
